# Security

Report suspected vulnerabilities privately to **contact@nomdelasociete.com**.
If GitHub’s “Report a vulnerability” option is available on this repository’s
Security tab, you may use that instead. Do not open a public issue.

Describe the affected revision/version, reproduction steps, and potential
impact. Use a minimal example with invented data. Do not include active tokens,
private PR content, or credentials for a real account.

Maintainers triage the current main branch and latest official release, when
one is available. Older releases have no guaranteed security backports. There
is no guaranteed response deadline; coordinated disclosure and optional reporter
credit will be agreed during triage.

If a credential was exposed, revoke it with its issuer; deleting a GitHub comment
or changing Git history does not invalidate it. Report hosted relay concerns
through the same private contact, identifying the affected service.
